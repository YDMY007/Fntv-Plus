### 实测踩到的坑（重要，别再踩）
1. **满铺画稿页上新建 Static 不渲染**：控件有文本、屏幕整块空白。旧版 EDIT 同症状，
   长期被误判成 `SetCtlColors` 失效。真因是该页「满铺画稿位图 + 多层自绘控件」的叠法下，
   新控件被判首帧遮挡而跳过绘制、之后遮挡消失也不补画。
   修：创建后 `SetWindowPos(HWND_TOP)` + `InvalidateRect(hwnd,0,1)`。
2. **进度页本体按钮完全失效**（用户报「原生按钮跑出来了」+「下一步点击无反应」，同一个根因）：
   `fnosSkinButton` 宏把句柄参数写成 `$1`，而宏内 `GetWindowLongW(...) i.r1` 的结果也回写 `$1`
   → **句柄当场被样式整数顶掉**，后续 `SetWindowLongW`/`SetWindowPos` 全打在无效句柄上，
   整个宏**静默失效**：按钮既没改成 BS_OWNERDRAW、也没挪位，保持原生外观停在原生位置。
   实测：修复前 `style=0x50010001`（BS_DEFPUSHBUTTON）+ 原生 rect；修复后 `style=0x5001000B`
   （BS_OWNERDRAW）+ 已挪到画稿药丸槽位。
   修：宏内不再拿 `$1` 当句柄 —— 直接引用调用方传入的寄存器（调用方用 `$R2`，宏内只碰 `$3-$6`），
   样式暂存 `$3`。
   ⚠ **为什么藏了这么久**：`BM_CLICK` 绕过命中测试，程序点击一直是通的 → 极易误判成「已生效」。
   验证皮肤/点击必须用**真实鼠标点击**或 `ChildWindowFromPointEx` 命中测试，别只看 style 值/挪位。
3. **进度页按钮还会被画稿层吃掉点击**（第 2 条修好后才暴露的第二层问题）：
   按钮的父窗口是主对话框，而满铺画稿所在的页面 dialog 同样是主对话框的子窗口、且创建更晚
   → 默认压在按钮之上，真实鼠标点击被 dialog 整层接走。
   修：skin 后 `SetWindowPos(btn, HWND_TOP, ...)`（按钮自绘不绘制，视觉零副作用）。
4. **进度页按钮残留原生外观**：先 `SW_SHOW` 再改样式 —— 显示瞬间按原生外观画一遍，
   改样式位不触发重绘，残影留在按钮表面。修：顺序反过来（先 skin 再 show）
   + `SWP_FRAMECHANGED` + `InvalidateRect`。

> 教训汇总：画稿页上的控件问题，**不要用程序触发点击来验证**（BM_CLICK/SendMessage 都绕过
> 命中测试），一律用 `ChildWindowFromPointEx` 或真实鼠标点击验；NSIS 宏展开是文本替换，
> 宏内使用的寄存器必须与调用方传入的寄存器**错开**，否则句柄会被静默打坏。

## 续：字体清晰度根治 + 图标修正（lc-1142 / lc-1143）

### lc-1142 字体发糊的真因与修法
- 真因：画稿只有 1560×1040(@2x) 一套，NSIS 侧 SS_BITMAP 缩到客户区（96dpi/100% 时 1560→780）。
  Windows 缩放 STATIC 位图默认 **COLORONCOLOR = 直接丢像素**（不是平滑缩放）→ 笔画断裂发虚。
  ⇒ 结论：**这个向导里"字不够清晰"先查位图缩放，别先调颜色字号**。
- 修法：每张画稿再出一套 **1x 原生渲染版** —— viewport 直接给目标尺寸 + CSS `zoom:0.5`
  让浏览器**按目标尺寸重新布局并光栅化**（zoom 触发 relayout；`deviceScaleFactor:0.5` 或
  `transform:scale` 都是"大尺寸渲染后降采样"，无效）。NSIS 侧两套都打包进 `$PLUGINSDIR\{1x,2x}`，
  运行时按 `GetDpiForWindow` 选目录（≤120dpi 用 1x 保证 1:1；>120dpi 用 2x 使缩小比<1，缩小优于放大）。
- 顺带：非整数 px 字号（12.5/13.5/17…）全部规整为偶数 —— 半像素也会发虚；次要字色整体加深一档。

### lc-1143 安装器图标（窗口左上角/任务栏）
- 坑一：**MUI2.nsh 内部对 `MUI_ICON` 有 `!ifndef` 兜底（NSIS 自带老图标）并据此自动发 Icon 指令**。
  在 MUI2 之后定义 MUI_ICON 会被默认值抢先 → 「图标怎么改都是 NSIS 那个老图标」。
  正解：在 `build/installer.nsh` 顶部（EB 生成脚本里先于 common.nsh/MUI2.nsh 被 include）写
  `!ifndef MUI_ICON` / `!ifndef MUI_UNICON` 兜底指向 `${BUILD_RESOURCES_DIR}\icon.ico`。
- 坑二：`build/icon.ico` 原来只有 **256×256 单尺寸**，标题栏/任务栏要 16/32 → Windows 硬缩必糊。
  重建为 16/24/32/48/64/128/256 七尺寸（lanczos3 + ≤32px 轻锐化 + PNG 压缩条目），270KB→85KB。
  生成脚本思路：sharp 逐尺寸出 PNG，再手写 ICO 头+目录拼装（Vista+ 支持 PNG 条目）。
- 工程习惯提醒：`build/icon.ico` 是 git 跟踪文件，改完要提交（二进制改动在 `git show --stat` 里
  显示为 `Bin xxx -> yyy bytes`，不算在 insertions 里，别以为没提交）。

## 续：季页选集「最多显示 11 集」根治（lc-1147，未提交）

### 真因（活体实证，48 集的剧 /v/tv/season/<id>）
原生选集横滑带有**两层裁剪**，美化竖排（D 段）只撞死了第二层的驱动：
1. 数据层分页：工具行「1 - 30 / 31 - 48」锚点按页拉数据（30/页），组件**整页交换**——
   点「31 - 48」后 DOM 从第 1~30 集整批换成 31~48 集，48 张卡从未同时存在过；
2. 渲染层虚拟窗口：只把横向窗口内的卡挂进 DOM（1680 视口首屏 10 张/1280 视口 9 张，
   即用户说的「最多 11 集」），靠横向滚动滑窗补卸。D 段 overflow 强制 visible 竖排后
   横向滚动死亡 → 窗口冻在首屏。
实验排除：CSS 没裁它；点锚点无效是因为翻页同样依赖滚 regulation 不动的容器（原文应为
「滚不动的容器」）；宽视口 + resize 能挂满当前页（30/30）但数据第二页仍要锚点翻页才拉。

### 修法（epListMerge.ts，用户拍板「样式一点不动」）
① 撑大视口：ms 宽 30000px + `window.dispatchEvent(resize)` → 组件重算窗口 → 当前页全量挂载
  （⚠ 重算只认真实 resize/scroll；合成 scroll 且 scrollLeft 不变时组件早退）。
② 多页克隆合并：逐个直调页码锚点的 React onClick 切页 → 每页全挂后 cloneNode(true) 收进
  自管容器 #fnos-eplist-full（插在 ms 之前）→ 显示完整列表，原生 ms absolute+opacity:0 移流。
保真：克隆类名与原生逐字节相同，D 段后代选择器全部自动生效；卡片是 <a href>，SPA 路由在
document 级拦 click → 跳转原生可用；卡内小按钮（已看/收藏）的 fiber 是 JS expando 克隆不复制
→ 容器点击委托：按「卡内子节点路径」找原生隐藏卡同位节点重派发，900ms 后整卡重克隆回显。
回填联动：patchEpisodeCard 按 href 找卡 → 容器文档序在前 → 补全集信息直接改到可见克隆卡。

### 实测踩坑（重要）
1. **React 翻页/重渲染会重建 ms 容器**，内联样式全丢 → 样式每次 ensure 现量现打，绝不假设还在。
2. **不能 display:none 藏 ms**：clientWidth 归零后虚拟窗口一张都挂不出；absolute+opacity:0 的
   clientWidth 仍是 30000，挂载照常（opacity 不影响 IntersectionObserver，clip 才影响）。
3. **缩略图是 IO 懒加载组件**：没滚进视口的卡里根本没有 <img>，克隆后永远是灰块。图片地址就
   挂在卡片子树 fiber memoizedProps.src 上（已加载/未加载都在）→ 克隆前从原生卡 fiber 挖地址，
   画到克隆卡占位层 background 上（约 48 卡 × fiber 上溯 12 层，一次性 <100ms）。
4. **页面加载偶发卡「加载中」**：NAS 前端在无头/后台环境约半数概率卡死，reload 1~2 次即过；
   另有**序号视图**（账号/客户端级记忆）——新环境默认数字网格、无 details 卡，验证脚本要先点
   「切换为卡片视图」。
5. 验证脚本：scripts/_verify_eplist_merge.cjs（注入编译产物 + CJS shim，不依赖发布补丁）。
