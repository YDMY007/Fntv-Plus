# 自定义刮削功能交接报告（Web 版 fpk → 桌面版）

> 交接目标：把 Web 版（Fntv-Plus-fpk）已上线的「自定义刮削」功能引入桌面版（Fntv-Plus，Electron）。
> 现状：README 对照表中「自定义刮削源回填」Web 版 ✅ / 桌面版 ❌。
> 本报告统计全部相关代码、协议、设置链路与移植适配点。基于 v1.10.2（commit 99fb33a）。

---

## 1. 功能清单与现状

| 子功能 | 入口 | 状态 | 说明 |
|---|---|---|---|
| **自定义刮削源回填** | 季页「选集」标题旁「⟳ 自定义刮削」按钮 | ✅ 已生效（v1.5.0） | 把标题/季号/锚点发给**用户自建刮削服务**，返回的分集标题与简介经飞牛官方编辑接口回填元数据 |
| **Jav 番号刮削** | 电影详情页右下浮动「⟳ jav 刮削」按钮 | ✅ 已生效（v1.10.0），**默认关** | 文件名番号 → javbus 抓取 → 回填标题（锁定），封面就地替换（纯前端视觉） |
| **自定义刮削服务** | 设置面板占位卡 | ⚠ 占位（v1.8.0），未正式生效 | 多源聚合接入，开发中，只有一张说明卡 + 「未正式生效」徽章，无逻辑代码 |

设计红线（两功能共用，移植时不得破坏）：
- **零系统改动**：不碰 trim.media 官方刮削、不改系统文件，元数据只走飞牛官方编辑接口 `getEditDetail / saveEditDetail`；
- **绝不倒打中文**：回填只允许「填空 / 覆盖占位符 / 中文覆盖英文」，已有中文永不被英文覆盖（`decideField` 裁决）；
- **字段锁**：写回必带 `title_locked / overview_locked`，防飞牛官方再刮削覆盖；
- **写后必复核**：save 后重新 get 比对，读不回来如实按失败计。

## 3. 协议与数据流

### 3.1 自定义刮削源（customScraper.ts，`runCustomScraper` 五步）

```
季页按钮点击
 ① 读季信息  POST /v/api/v1/item/getEditDetail {item_guid: 季guid, nonce}
    → 提取锚点链：tmdb_id(纯数字最强) > trim_id(tt…) > imdb_id > douban_id + guid + 标题 + 季号
 ② 枚举本季集  POST /v/api/v1/item/list {parent_guid, exclude_folder:1, sort_column:'sort_title', …}
    → type==='episode' 的 {guid, index}；失败回落 DOM a[href="/v/tv/episode/<guid>"]
 ③ 请求用户自建刮削服务（浏览器直接 fetch，见 §6.2 CORS 注意点）
 ④ 逐集管线（4 路并发，CONCURRENCY=4）：
    getEditDetail 读全量 → decideField 裁决 → saveEditDetail 全量回写（改的字段 + *_locked:true + nonce）
    → getEditDetail 读回复核 → patchEpisodeCard DOM 即时补丁（不动清晰度胶囊 span）
 ⑤ 按钮状态机反馈：⏳回填中 n/N / ✓已回填n项 / ⚠回填n·失败m / ⚠n集未匹配 / ✓数据已最新 / ⚠未配置
```

**③ 的请求/响应协议**（设置卡文案里公开承诺，改动即破坏兼容）：

请求 POST JSON：
```json
{
  "title": "剧集标题", "season": 2, "tmdbId": "12345",
  "trimId": "tt1399", "imdbId": "…", "doubanId": "…", "guid": "季guid",
  "episodes": [ { "index": 1, "guid": "集guid" }, … ]
}
```

响应 JSON（字段宽容映射，`fetchFromCustomScraper` 规范化）：

| 响应字段 | 容错别名 | 缺省语义 |
|---|---|---|
| `episodes` | `data` | 缺数组 → 报错「响应缺少 episodes 数组」 |
| `index` | `episode` `number` | 缺省按数组序号+1 |
| `title` | `name` | null/缺省=不动该字段 |
| `overview` | `description` | null/缺省=不动该字段 |

**合并裁决 `decideField(cur, zh, en, placeholder)`**（纯函数，语义必须原样保留）：
- 新值为空/占位 → 不动；当前为空 → 回填；
- 当前无 CJK 且新值有 CJK → 覆盖（中文覆盖英文）；
- 其余（已有中文等）→ 不动；
- `isPlaceholderTitle`：`第N集 / episode N / #N` 视为「无数据」可覆盖。

### 3.2 Jav 番号刮削（jav.ts + jav.go）

```
电影详情页（/v/movie/<32hex>）浮动按钮
 ① getEditDetail 读条目 → 取当前标题（番号提取在后端）
 ② ipc 'jav:lookup' {title, guid} → 后端 javExtractCode：
      FC2 正则 (?i)\b(FC2(?:-PPV)?)-?\s?(\d{6,10})\b
      标准正则 \b([A-Za-z]{2,6})-?\s?(\d{2,5})\b，字母段过黑名单
      （HDR/DV/CD1/PART2/REMUX… 等技术词/分段词不算番号，防误识别）
    → 详情页直取 https://{域名}/{番号} → 404 时搜索页兜底取首个 movie-box
    → 宽容正则解析：标题(h3)/封面(bigImage→cover)/发行日期/类别(/genre/ 链接)/演员(avatar-box)
    → 进程内缓存 24h；网络走 extHTTP（自定义代理 > 系统直连；javbus 国内直连不通）
 ③ 命中 → saveEditDetail 回写 title（title_locked，全量读改写 + nonce），读回复核
 ④ 封面：ipc 'jav:image' {url} → 后端代理下载（域名白名单=设置的 javBusDomain 含子域，
    16MB 上限）→ dataURL → 就地替换 hero 海报 <img>（纯前端视觉，**不写服务端 posters**——
    fnOS posters 为数组结构，写回格式未抓包验证，宁缺勿错）
 ⑤ 按钮反馈：未识别番号 / javbus失败 / ✓已回填+封面 / ⚠回填失败（写回未确认）
```

安全开关：后端 handler 第一道闸 `javOn()`（设置 javEnabled≠1 直接 ok:false），前端按钮也受 S.javEnabled 控制不挂载——双层门禁都要保留。

## 4. 设置项与持久化

共 4 个 config 键（Web 版存 NAS 端 config.json 平铺 Extra，与桌面版 config.json 字段名**已对齐**——shim 注释明示）：

| config 键 | 前端 IPC 写入通道 | 默认值 | 说明 |
|---|---|---|---|
| `customScraperEnabled` | `settings:set-custom-scraper-enabled` | false | 自定义刮削源开关 |
| `customScraperUrl` | `settings:set-custom-scraper-url` | '' | 自建刮削服务完整地址（http/https） |
| `javEnabled` | `settings:set-jav-enabled` | false | Jav 刮削开关（默认关） |
| `javBusDomain` | `settings:set-jav-bus-domain` | ''（回退 `https://www.javbus.com`） | javbus 域名，可填镜像；后端归一化剥 scheme/尾斜杠 |

读取统一走 `settings:get`（Web 版 GET `/app/fntvplus/api/settings`；桌面版 ipc 直接回 config 全量）。
持久化通用规则（shim `settingKey()` 即参考实现）：`settings:set-<kebab>` → camelCase 键。这 4 条不在 `SETTINGS_KEY_MAP` 特例表里，全走通用规则——**桌面版 main 进程的 settings 通道只需支持任意键落 config.json 即天然兼容**。

另有模块自举：customScraper.ts 模块加载即 `settings:get` 拉一次设置（`bootstrapFromSettings`），不依赖用户开过设置面板；开且在季页则补挂按钮。

## 6. 桌面版移植适配点（与坑）

### 6.1 jav.go 后端的落地方式（唯一硬骨头，二选一）

- **方案 A：Node 重写进 main 进程**。jav.go 全部依赖是 `net/http` + 正则 + html 反转义 + 进程内 map 缓存，无 CGO/平台依赖，Node 用 `fetch`/`https` + 同款正则可直接转译（≈200 行）。正则表、番号黑名单、解析字段、404→搜索兜底链、24h 缓存、封面域名门禁逐项对照 §3.2，测试用例照 `jav_test.go` 五个 Test 搬。
- **方案 B：Go sidecar**（本仓库直接编译一份只含 bridge/jav 的微型 CLI，Electron spawn）。保真度最高、零转译风险，代价是随包分发二进制。

选型建议：桌面版若已有 Node 侧网络栈（代理设置等），方案 A 更顺；若追求与 Web 版行为逐字节一致，方案 B。

### 6.2 CORS：自定义刮削服务请求路径

Web 版 `customScraper.ts` 的 `fetch(自建地址)` 发生在**页面上下文**（origin=飞牛 NAS），跨域要求用户的刮削服务返回 CORS 头——Web 版一直如此工作（自建服务天然可配 CORS）。桌面版两种选择：
1. 保持页面直连（行为一致，服务仍需 CORS）；
2. 改经 main 进程代理请求绕开 CORS（对用户更友好，但请求封装点在 customScraper.ts 的 `fetchFromCustomScraper` 单函数，正好是唯一改动面，协议不变）。
建议桌面版走方案 2，并把「请求由桌面端代理发出」写进设置卡文案。

### 6.3 其余逐项

| # | 适配点 |
|---|---|
| 1 | **导航钩子**：桌面版 embyWall 若同构，四处 `schedule*` 接线（§2.3 末行行号）缺一处都会出现「深链进季页按钮不挂」或「离开页面按钮残留」 |
| 2 | **按钮挂载回退链**：`findSelectHeading` 被「补全集信息」按钮占用时退而挂到 `#fnos-epfix-btn` 宿主——前提是桌面版也有 epBackfill 功能；若桌面版**没有**「补全集信息」，把 epBackfill 的十个管线函数一并带过去（本来就是纯函数集合） |
| 3 | **行内 `!important` 底色**：jav.ts 浮动按钮的背景是行内 `!important`（v1.10.2 修复：页面背景自定义的 `body>div` 清透规则会清掉普通行内底色）。桌面版若没这规则则不受伤，保留亦无害 |
