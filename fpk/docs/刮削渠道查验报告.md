# 刮削渠道查验报告 —— 除 TMDB 外还有哪些官方渠道？

> 查验日期：2026-09-13
> 查验范围：① 本仓库（Fntv-Plus Web 版）当前实际接入的所有外部数据渠道及其性质；② 生态内其他可作为刮削源的官方开放 API 盘点。
> 查验方式：通读 `src/go/internal/bridge/` 全部数据链代码（tmdbshow / doubansync / sync / person / hot / skip / danmaku / danmu_api）+ 前端 `customScraper.ts` / `epBackfill.ts` + proxy 域名白名单，并逐一上网核实各数据源官方 API 的最新状态。

---

## 一、结论（TL;DR）

**有。刮削/元数据这条线上，除 TMDB 外，本项目实际已接入的官方开放渠道还有 3 个：Bangumi（api.bgm.tv）、Trakt（api.trakt.tv）、AniSkip（api.aniskip.com），另有 theintrodb、AniList 两个官方公开 API 用在跳片头片尾链路里。**

但按用途细分，结论是：

| 用途 | 官方渠道 | 现状 |
|---|---|---|
| 影视元数据刮削（标题/简介/分集/图片） | **只有 TMDB 一个** | 项目内唯一官方刮削源；生态内可选 Fanart.tv（图）、TVMaze（欧美剧）、OMDb（IMDb 评分）、MAL 官方 API（动漫） |
| 动漫元数据/进度同步 | Bangumi（官方 v0）| ✅ 已接入（官方 API + 个人令牌） |
| 观看记录同步 | Trakt（官方 + OAuth 设备授权）| ✅ 已接入（官方 API） |
| 中文影视元数据 | **零官方渠道** | 豆瓣官方 API 已关闭、B 站无开放元数据 API——这正是项目豆瓣走 cookie 逆向的根本原因 |

## 二、本项目当前接入的全部外部渠道逐个查验

### A. 有官方开放渠道的（✅ 官方 API）

| # | 渠道 | 官方端点 | 鉴权 | 项目内用途 | 代码位置 |
|---|---|---|---|---|---|
| 1 | **TMDB** | `api.themoviedb.org/3` + `image.tmdb.org` | 用户自配 API Key（v3 key 或 v4 Bearer） | 剧集信息卡完整聚合、双语分集回填、热门发现、演员页全量作品、评分/类型/播出状态补全 | `bridge/tmdbshow.go`、`person.go`、`hot.go`、`sync.go(doubanEnrich)`、前端 `epBackfill.ts` |
| 2 | **Bangumi** | `api.bgm.tv/v0` | 个人访问令牌（Bearer，读公开数据可不带） | 番剧在看/看过同步、每日放送日历、跳过链中取日文名做 MAL 映射 | `bridge/sync.go`、`hot.go` |
| 3 | **Trakt** | `api.trakt.tv` + `auth.trakt.tv` | OAuth 2.0 设备授权（用户自己的 client_id/secret） | scrobble 播放上报、已观看同步（后端 8 条路由） | `bridge/bridge.go:362-444` |
| 4 | **AniSkip** | `api.aniskip.com/v2` | 无需 key，公开 | 动漫片头/片尾/前情回顾跳过时间点 | `bridge/skip.go:166` |
| 5 | **theintrodb** | `api.theintrodb.org/v3` | 公开（其 FAQ 声明不适合服务端/商业用途） | 非动画剧集片头/片尾兜底（tmdb_id/imdb_id 查询） | `bridge/skip.go:209-229` |
| 6 | **AniList** | `graphql.anilist.co` | 无需 key，公开 GraphQL | 仅用于 MAL id 映射（与 Jikan 双路互备） | `bridge/skip.go:108` |

要点补充：

- **TMDB 是唯一承担"刮削"职责的官方渠道**——即主动按标题/ID 拉取并回填条目元数据（分集标题、简介、演职人员、图片、评分）。其余官方渠道都是"同步/增强"性质。
- TMDB 与 Bangumi 都做了传输多路兜底（自定义代理 → 免梯子直连 IP/公共 DNS 直连 → 系统直连），TMDB 详情还有磁盘永久缓存（`tmdb-cache/`），是对国内网络环境适配的关键。

### B. 无官方渠道、走非官方/逆向接口的（⚠️）

| # | 渠道 | 实际做法 | 项目内用途 | 代码位置 |
|---|---|---|---|---|
| 7 | **豆瓣** | 伪装浏览器 UA + 用户手动粘贴 cookie，调网页端内部接口：`/j/subject_suggest` 搜索、`/j/subject/{id}/interest` 标记、条目页 HTML 正则抓评分、`m.douban.com/rexxar/api/v2` 热门榜单 | 在看/看过同步、评分显示、热门剧更新浮层 | `bridge/doubansync.go`、`sync.go:346-376`、`hot.go` |
| 8 | **Bilibili** | WBI 签名调 web 端内部接口搜番剧/拉弹幕 XML（`api.bilibili.com`），可选 SESSDATA cookie | 网页弹幕数据链 | `bridge/danmaku.go` |
| 9 | **Jikan**（`api.jikan.moe`） | 社区维护的 **非官方** MyAnimeList API | MAL id 映射一路 | `bridge/skip.go:94` |
| 10 | **自建弹幕源（danmu_api）** | 用户自己部署的弹幕服务（`/api/v2/search/anime` 等三端点，弹弹play 风格） | 弹幕备选源 | `bridge/danmu_api.go` |

其中**豆瓣是最典型的"没有官方渠道"案例**：豆瓣曾有官方 API v2 开放平台，但已关闭且不再对个人开放申请（本次已上网核实），社区通用做法就是抓包 App 内部接口——本项目选择的是网页端接口 + 用户自带 cookie 的轻量方案，并做了并发闸门、系列级缓存防风控。

### C. 渠道不设限的用户自定义通道

- **自定义刮削源回填**（`customScraper.ts`，v1.5.0）：用户配置任意 HTTP 地址，应用 POST `{title, season, tmdbId, episodes:[{index,guid}]}`，期望返回 `{episodes:[{index,title,overview}]}`，逐集合并回填飞牛（只覆盖空值/可升级值，不倒打中文，`*_locked` 防官方刮削覆盖）。**这个通道本身不限定数据源**——理论上可以指向任何官方/非官方刮削服务，是未来接入新官方渠道的现成入口。

## 三、生态盘点：除 TMDB 外还有哪些官方开放刮削渠道可扩展

以下为本次上网逐一核实的现状（2026-09），按与本项目契合度排序：

### 1. Fanart.tv —— 官方，免费，与本项目最契合 ⭐
- **性质**：官方 API v3（`api.fanart.tv`），社区维护的高质量影视图库，免费注册账号即可生成个人 API key。
- **内容**：透明底高清 Logo（clearlogo/hdclearlogo）、背景图、海报、横幅、碟面等，质量普遍高于 TMDB 自带图库。
- **契合点**：本项目「Logo 自定义/详情页美化」目前依赖 TMDB `images`（`include_image_language=zh-CN,en,null`），接 Fanart.tv 可显著补齐中文/高清透明 Logo 缺口。
- **限制**：图片以 TMDB/IMDb ID 为键，需先经 TMDB 拿外部 ID（项目已有 `external_ids` 数据）。

### 2. TVMaze —— 官方、完全免费、无需 key
- **性质**：官方 REST API（`api.tvmaze.com`），免费开放，无需任何 key，限速 20 次/10 秒/IP，数据 CC BY-SA（需署名）。
- **内容**：欧美剧集元数据、分集列表、演员、图片，支持按 TVDB/IMDb ID 反查。
- **短板**：无中文数据，对中文用户只能作辅助源（分集结构/播出日期核对）。

### 3. OMDb —— 官方，免费额度 1000 次/天
- **性质**：官方 API（`www.omdbapi.com`），邮箱免费领 key（1000 次/天），$1/月 Patreon 解除限制；**非商业许可（CC BY-NC 4.0）**。
- **内容**：IMDb 评分/票数/奖项等（IMDb 自身无官方公开 API，OMDb 是事实上的间接官方数据渠道）。
- **契合点**：观看列表页的评分显示目前是 TMDB + 豆瓣双评分，OMDb 可补 IMDb 评分列，且项目已持有 IMDb ID（TMDB `external_ids`）。

### 4. MyAnimeList 官方 API v2 —— 官方，注册即用
- **性质**：官方（`api.myanimelist.net/v2`），在 MAL 注册应用得 Client ID，请求带 `X-MAL-CLIENT-ID` 头即可读公开数据。
- **内容**：动漫条目/分集/排名/用户清单。
- **注意**：本项目跳过链里用的 Jikan 是其**非官方**社区镜像；若要上官方 MAL 渠道，注册 Client ID 即可替换，且可顺带获得 MAL 打分数据。

### 5. TheTVDB —— 官方但已不再免费 ❌
- **性质**：API v4 仍存活，但免费开发者档已取消——需商业许可、用户订阅（约 $12/年）或成为活跃贡献者。
- **结论**：不建议作为扩展方向；历史上它曾是剧集刮削主力，如今已被 TMDB 全面取代。

### 6. 其他可留意的
- **Kitsu**（动漫，官方开放 REST，无需 key）、**Wikidata Query**（官方开放 SPARQL，可做豆瓣号/IMDb/TMDB 编号互查的映射桥，对豆瓣 ID 解析兜底有想象空间）。
- **IMDb / 豆瓣 / B 站**：三者均**无**官方公开元数据 API——IMDb 只有离线数据集，豆瓣官方 API 已关闭，B 站开放平台不含影视元数据。中文元数据在可预见期内只能继续依赖豆瓣逆向或 TMDB 中文化数据。

---

## 四、对照小结

1. **「除 TMDB 外还有没有官方渠道」——项目内答案：有 3 个在跑（Bangumi、Trakt、AniSkip），外加 theintrodb/AniList 两个辅助官方源；但真正干"刮削"活（拉元数据回填）的官方渠道目前只有 TMDB 一个。**
2. **中文元数据没有官方渠道可换**：豆瓣/B 站均无官方开放 API，豆瓣链路的 cookie 逆向是当前唯一可行路线，继续做好防风控（并发闸门、系列缓存、cookie 失效识别）即可。
3. **最值得扩展的官方渠道是 Fanart.tv**（免费 key、补高清透明 Logo，直接增强现有 Logo/美化功能）；其次是 OMDb（IMDb 评分显示）与 MAL 官方 API（替换非官方 Jikan）。三者都能复用现有 TMDB `external_ids` 与"自定义刮削源"通道的基建，改动面小。
4. 本项目已把"官方渠道"与"逆向渠道"在架构上分得很清楚：官方渠道全部走标准鉴权（API Key / Bearer / OAuth），逆向渠道全部要求用户自带 cookie + 浏览器 UA + 防风控节流，proxy 域名白名单（`bridge.go:40-48`）与设置面板分类一一对应，后续接新官方源照此模式加即可。
