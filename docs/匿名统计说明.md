# 匿名使用统计说明（Web 版 / fpk）

> 对应实现：`src/go/internal/stats/stats.go`（后端心跳）、
> `src/preload/plugins/embyWall/modals/telemetry.ts`（设置面板「关于」页的卡片）。
> 与桌面客户端 [Fntv-Plus](https://github.com/YDMY007/Fntv-Plus) 的
> `src/main/handlers/plugins/usageStats.ts` 同一设计口径。

## 为什么做这个

只想知道一件事：**有多少台 NAS 真的在用这个应用**。

没有它，改动是否值得、某个平台要不要继续维护、新版有没有人升级，全靠猜。所以这里刻意
把采集面压到「够算人数」为止 —— 能算出活跃台数与版本分布，但**还原不出任何一台 NAS
的使用细节**。

## 采集了什么

每台 NAS 每天最多一次，payload 只有 6 个字段：

| 字段 | 内容 | 说明 |
| --- | --- | --- |
| `aid` | 本机随机生成的 UUID | 与账号 / 设备 / 机器码 / 安装路径**全部无关**；面板可一键重置 |
| `v` | 应用版本号 | 例如 `1.3.0-223`，用于看版本分布 |
| `os` | 固定为 `fnOS` | 用于和桌面客户端（Windows/macOS/Linux）区分开 |
| `arch` | CPU 架构 | `amd64` / `arm64` |
| `d` | 本地日期 | `YYYY-MM-DD`，兼容只认单日字段的老服务端 |
| `days` | 日期数组 | 断网时攒下的欠报日期，恢复后一并补发（最多 8 天） |

## 不采集什么

- **不读、不存 IP**：服务端代码里连 `cf-connecting-ip` 都不碰（见其 `worker.js` 注释的隐私底线）；
- **不读 User-Agent**；
- 不采集账号、媒体库内容、文件路径、NAS 主机名、盘位、观影记录、播放了哪一集；
- **不采集使用时长**，也不做任何「某台 NAS 干了什么」的行为埋点。

服务端按 `(aid, 日期)` 主键去重 —— 同一天重复上报直接忽略，所以**只能聚合成「台数」**。

## 什么时候会发

- 触发点是**「今天确实有人打开了增强页面」**（反代注入成功那一刻），不是进程启动 ——
  装了但没人用的 NAS 不会被算作活跃，数字更诚实；
- 同一天只记一次（页面反复刷新不会灌水）；
- 记录后由后台循环发出：启动 60 秒后检查一次，此后每 6 小时一次；
- **只有真的有待报日期时才会走网络**，没记录就完全不发请求。

## 四层「不发」的保证

1. **服务端未配置** → 一个字节都不发；
2. **用户在设置面板关掉开关** → 立即停止（连本地使用记录都不再写）；
3. **开发版**（版号解析为 `dev`）→ 默认不上报，避免作者自测把数据灌水；
4. **网络不通** → 静默失败，只写一条本地日志。不弹窗、不报错、不重试风暴
   （最快 6 小时后才再试），用户全程无感。

失败时当天的日期会留在本地欠报队列（最多 7 天），网络恢复后自动补发 —— 服务端接受
±7 天的日期并按 `(aid, 日期)` 去重，所以偶发断网几天不会让活跃台数被低估。

## 用户能控制什么

设置面板 →「关于」页 →「📊 匿名使用统计」卡：

| 操作 | 效果 |
| --- | --- |
| 参与匿名统计（开关） | 关闭后立即停止记录与上报 |
| 立即上报一次 | 手动验证链路是否通（面板显示成功/失败原因） |
| 重置匿名 ID | 换一个新 UUID，**与历史数据彻底断开**，旧 ID 无法再关联到本机 |

面板里只显示匿名 ID 的**前 8 位**（够核对，又不至于被复制滥用）；完整 ID 只留在 NAS 本机
`config.json` 里，设置 API 下发时一律遮蔽为 `""` + `statsAnonIdSet: true` 标记。

## 服务端与数据归属

复用桌面版同一个接收端（Cloudflare Worker，见 Fntv-Plus 仓库的 `stats-server/`）：走现成的
`/ping` 路由，靠 `os` 字段把 NAS 端单独读出来 —— 作者在 `/stats` 的 `systems` 分布里就能看到
「fnOS 台数」，**本次改造不需要改服务端、也不需要重新部署**。

数据只用于作者自己看活跃度趋势，不外传、不商用、不投喂给任何第三方；反馈内容与日志另见
反馈弹窗（由用户主动提交）。

> 想完全不参与：把开关关掉即可，或在防火墙层面屏蔽 `stats.690075.xyz` /
> `fntv-stats.122983191.workers.dev`（后者是兜底端点）—— 两条路都不影响任何功能。
